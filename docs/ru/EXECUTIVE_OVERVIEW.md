# Краткий обзор проекта для владельца

## Финальная цель

Построить проверяемую production-grade систему исследования и управления нативным Bybit Futures Grid Bot. Система рассчитана на целевой объём **700 инструментов × 10 лет × 1m**: около **3,681 млрд торговых свечей** и до **7,363 млрд строк свечей**, если параллельно хранить trade-price и mark-price.

Результатом проекта должен стать не «набор скриптов», а управляемая цепочка:

```text
история → проверенные данные → признаки/кандидаты → честный backtest
→ устойчивые параметры → immutable strategy release
→ shadow live → manual live → контролируемое масштабирование
```

## Главное архитектурное решение

Проект разделён на четыре независимо запускаемых приложения:

1. `grid-data` — загружает, проверяет, чинит и уплотняет историю.
2. `grid-research` — строит признаки, находит проторговки, подбирает параметры и тестирует их.
3. `grid-release` — собирает и независимо проверяет неизменяемый пакет стратегии, затем выполняет promotion/revoke.
4. `grid-live` — работает только с текущим рынком и promoted release; исторический lake и optimizer ему не нужны.

Поэтому после завершения исследования владелец сможет запустить **только live**, не запуская скачивание истории или подбор параметров.

## Как достигается скорость

- для trade-price 1m, mark-price 1m и funding используется публичный V5 REST; tick-архивы не скачиваются;
- данные хранятся в Parquet/ZSTD, а не CSV;
- DuckDB и Polars читают только нужные столбцы и партиции;
- данные делятся по месяцу и стабильному symbol bucket, чтобы не создавать миллионы мелких файлов;
- общие rolling features считаются один раз;
- дорогая симуляция запускается только на разреженном наборе кандидатов, а не на каждой минуте и каждом наборе параметров;
- расчёты разбиваются на возобновляемые shards с halo;
- каждый результат имеет manifest/receipt и переиспользуется по content identity;
- Rust/C++ добавляется только после профилирования реального bottleneck.

## Что live не делает

Live не:

- открывает исторический Parquet lake;
- запускает DuckDB research queries;
- подбирает параметры;
- читает notebook/папку последнего эксперимента;
- меняет promoted release;
- повторяет вслепую create/close после timeout.

При неопределённости live блокирует новые действия и сверяет локальное состояние с Bybit.

## Безопасность

Базовые правила:

- ключ без withdrawal;
- целевой production — отдельный subaccount и live-host;
- research/data не получают trade credentials;
- первая реальная торговля только после shadow и ручного подтверждения;
- один активный или uncertain grid на symbol;
- intended loss на сетку по текущей модели не выше 5 USDT;
- emergency stop сохраняется после перезапуска до ручного `/resume`;
- live стартует только с promoted, hash-verified release.

## Порядок реализации

1. Документация и гейты.
2. Feasibility/benchmark на репрезентативных данных.
3. Canonical historical store.
4. Feature/candidate platform.
5. Outcome simulator и portfolio backtest.
6. Robust parameter selection.
7. Strategy release registry.
8. Shadow live без торговли.
9. Manual minimal-mainnet.
10. Постепенное масштабирование по фактам.

Переход к live не разрешается автоматически после красивого backtest. Нужны OOS/out-of-symbol проверки, costs/funding, stress, concentration, restart/reconciliation и emergency evidence.
